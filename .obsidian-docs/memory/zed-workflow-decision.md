Схема работы по vaultscout: сессия Claude Code запускается в отдельном
терминале, Zed используется только как редактор для набора кода.
Редактор git оставлен по умолчанию (nano) — `core.editor` намеренно НЕ
настраивался.

**Why:** Проверено по первоисточникам 2026-09-17. Zed не реализует
протокол IDE-интеграции Claude Code (запрос открыт с июня 2026, ответа
команды Zed нет), поэтому запуск агента во встроенном терминале Zed не
даёт ни выделенного фрагмента, ни открытых файлов, ни диагностик — это
такой же слепой терминал, только уже. Панель агента в Zed (через ACP,
бета с апреля 2026) контекст даёт, но забирает полноэкранный вывод и
добавляет слой беты, а настройки профилей и скиллы Zed к внешнему агенту
не применяются автоматически. В режиме «пользователь пишет, агент ведёт»
агенту важнее показывать длинные разборы и ревью, чем видеть курсор.
`EDITOR=zed --wait` отклонён пользователем: nano его устраивает и
работает по SSH без графики, где Zed бы не открылся.

**How to apply:** Не предлагать повторно панель Zed, настройку
`core.editor` или форк Zed с IDE-интеграцией — решение принято
осознанно. Вернуться к вопросу, только если Zed реализует протокол
IDE-интеграции в основной ветке. Побочный факт: список потоков в боковой
панели Zed показывает сессии всех проектов машины (импорт отбрасывает
только сессии без рабочей папки) — это поведение Zed, не сбой.
