Ветка `stage-1-vault-parser` (создана 2026-09-17, не закоммичена на конец
сессии). Готово: модуль `src/vaultscout/vault.py` — модель `Note`
(path относительно корня vault, title, frontmatter, body), заглушка
`VaultError`, функция `split_frontmatter` (проверена вручную на 8 случаях,
все верны). Тестов на неё ещё нет.

План шага (согласован с пользователем):
1. Тесты `tests/test_vault.py` на split_frontmatter — 5 случаев: обычный
   frontmatter, без frontmatter, незакрытый блок, битый YAML, пустой блок.
2. Обход vault: только `.md`, пропускать скрытые папки (`.obsidian`,
   `.trash`), для каждого файла → Note. Тесты на tmp_path.
3. PR, ревью, мерж → отметить этап 1 в README.

Решения: битый frontmatter не роняет разбор — пустой словарь, весь текст
в тело (логирование предупреждения добавим позже). Разбор заголовков и
wikilinks — НЕ парсер, а chunking (следующий шаг после парсера):
парсер отвечает «что за заметка», chunking — «на какие части делится».

Мелочь на ревью: в split_frontmatter первая строка сравнивается без
`strip()` (строка `--- ` с хвостовым пробелом не распознаётся), внутри
цикла strip есть; переменная `string` для тела лучше назвать `body`.

Открытый вопрос: есть ли на другой машине пользователя наполненная папка
`local/` (в git не едет) — пользователь не помнит, проверить там
командой `ls ~/Projects/vaultscout/local`.

**Why:** план и границы шага не восстанавливаются из кода/git — в репо
только заготовка без тестов.

**How to apply:** следующая сессия начинается с пункта 1 (тесты).
Связано с [[explain-from-reasoning]], [[one-step-per-message]].
